Your first call

Buy data with REST or MCP

Preview for free, then approve a single purchase. You do not need a customer account or a DataForSEO API key.

{{MODE_NOTE}}

This example uses Google SERP: up to 10 organic Google results for one search query. Current price: {{SERP_PRICE}} USDC. The live catalog and payment request specify the applicable network and price. This service is for businesses only (B2B) and is subject to the terms of use.

1. Browse and validate your input for free

These commands do not make a payment. Preflight validates your input and checks the current price. HTTP 402 on an unpaid data request is a payment requirement.

curl {{BASE_URL}}/api/v1/services

curl -X POST {{BASE_URL}}/api/v1/preflight/google-serp \
  -H 'content-type: application/json' \
  -d '{"keyword":"running shoes","location_code":2840,"language_code":"en"}'

2. Download the example and run a preview

Requires Node.js 24 or later. Run the following setup commands in a dedicated directory. The example supports REST and MCP. Without APPROVE_USDC, it only reads the catalog and runs preflight.

mkdir agent-api-buyer
cd agent-api-buyer
npm init -y
printf '%s\n' '.env.buyer' 'agent-api-purchase.json' 'node_modules/' >> .gitignore
npm install @x402/fetch@2.28.0 @x402/evm@2.28.0 @x402/mcp@2.28.0 @modelcontextprotocol/sdk@1.32.1 viem@2.57.7
curl -fSL {{BASE_URL}}/examples/buyer.mjs -o buyer.mjs
node buyer.mjs

You can inspect the complete example code. Before signing once, it checks the price, recipient, official USDC contract, Base network and requested resource. An existing purchase file blocks another purchase in the same directory.

3. Set up your wallet locally

To buy data, you need your own buyer wallet with USDC on Base. The x402 facilitator covers the gas fee for this purchase. Enter your key only in a local .env.buyer file. Keep the file and key out of chats, Git and web forms.

BUYER_PRIVATE_KEY=YOUR_DEDICATED_BUYER_KEY
MERCHANT_ADDRESS={{PAY_TO_ADDRESS}}

The recipient above is the merchant wallet. The example also checks this address against the actual payment request. It rejects a different recipient or an amount above the approved limit.

4. Approve exactly one purchase

Choose REST or MCP. The REST command below authorizes one SERP purchase up to the displayed amount. It sends a real USDC payment.

chmod 600 .env.buyer
APPROVE_USDC={{SERP_PRICE}} node --env-file=.env.buyer buyer.mjs

The response is saved in agent-api-purchase.json (file permissions 600), including the request ID and result token. The private key and payment signature are not saved. Keep this file private. Do not delete it to retry a purchase whose outcome is uncertain.

Use MCP

Endpoint: {{BASE_URL}}/mcp, using Streamable HTTP. The configuration below connects a compatible MCP client. The exact configuration format depends on your client. Connecting alone does not make a payment.

{
  "mcpServers": {
    "agent-data-api": {
      "type": "http",
      "url": "{{BASE_URL}}/mcp"
    }
  }
}

Client only supports local (stdio) servers? Use the generic open-source bridge mcp-remote; no separate package from us is needed. It forwards to the same endpoint, so free tools work and paid tools still answer with the payment requirement:

{
  "mcpServers": {
    "agent-data-api": {
      "command": "npx",
      "args": ["-y", "mcp-remote@0.15.2", "{{BASE_URL}}/mcp"]
    }
  }
}

list_services reads the catalog; preflight validates input. get_result retrieves an existing result with its token. wishlist submits a tool suggestion for free. If enabled, free_sample provides a limited free sample. retry_request explicitly retries a paid request that failed and triggers a new upstream data request without a new USDC payment.

Paid tools require an x402-capable buyer client. A standard MCP client only receives the payment requirement. To make a single MCP purchase instead of the REST purchase, use the same example:

APPROVE_USDC={{SERP_PRICE}} node --env-file=.env.buyer buyer.mjs --mcp

The example uses @x402/mcp and enforces the same limits as REST. It does not grant blanket approval for other tools or additional payments.

If a response is missing

After sending a payment authorization, a timeout, disconnected connection or error response is not proof that no payment occurred. Do not automatically buy again or create a new payment authorization.

  1. Keep the existing purchase file and public transaction ID.
  2. If you have the request ID and result token, retrieve the stored request:
curl {{BASE_URL}}/api/v1/results/REQUEST_ID \
  -H 'Authorization: Bearer RESULT_TOKEN'

The token is part of your private response. If the entire response is lost, the same originally signed REST request can return the stored result within 15 minutes, provided you still have it stored securely locally. The example does not save the signature. If you lack the request ID or token, contact {{CONTACT_EMAIL}} with the public payment receipt. Do not send private keys or payment signatures.

After a confirmed upstream failure, the service allows one explicit free retry at POST /api/v1/results/REQUEST_ID/retry with the same Bearer token. Check the request status before deciding to retry; no new USDC payment is needed. Inputs and results are deleted after 30 days.
