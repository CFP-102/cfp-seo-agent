Erster Abruf

Daten kaufen mit REST oder MCP

Erst kostenlos prüfen, dann einen einzelnen Abruf freigeben. Sie benötigen kein Kundenkonto und keinen DataForSEO-Schlüssel.

{{MODE_NOTE}}

Das Beispiel nutzt Google SERP: bis zu 10 organische Google-Ergebnisse zu einem Suchbegriff. Aktueller Preis: {{SERP_PRICE}} USDC. Das maßgebliche Netzwerk und der Preis stehen im Live-Katalog und in der Zahlungsanforderung. Das Angebot richtet sich an Unternehmer (B2B); es gelten die Nutzungsbedingungen.

1. Kostenlos ansehen und Eingabe prüfen

Diese Befehle enthalten keine Zahlung. Preflight bestätigt gültige Eingaben und den aktuellen Preis. HTTP 402 bei einem unbezahlten Datenabruf ist eine Zahlungsanforderung.

curl {{BASE_URL}}/api/v1/services

curl -X POST {{BASE_URL}}/api/v1/preflight/google-serp \
  -H 'content-type: application/json' \
  -d '{"keyword":"running shoes","location_code":2840,"language_code":"en"}'

2. Beispiel herunterladen und Vorschau starten

Voraussetzung: Node.js 24 oder neuer. Alle folgenden Installationsbefehle laufen in einem eigenen Verzeichnis. Das Beispiel unterstützt REST und MCP. Ohne APPROVE_USDC führt es nur Katalog und Preflight aus.

mkdir agent-api-buyer
cd agent-api-buyer
npm init -y
printf '%s\n' '.env.buyer' 'agent-api-purchase.json' 'node_modules/' >> .gitignore
npm install @x402/fetch@2.28.0 @x402/evm@2.28.0 @x402/mcp@2.28.0 @modelcontextprotocol/sdk@1.32.1 viem@2.57.7
curl -fSL {{BASE_URL}}/examples/buyer.mjs -o buyer.mjs
node buyer.mjs

Der vollständige Beispielcode ist lesbar. Er prüft Preis, Empfänger, offiziellen USDC-Vertrag, Base-Netzwerk und angefragte Ressource, bevor er einmal signiert. Eine bestehende Kaufdatei blockiert einen weiteren Kauf im gleichen Verzeichnis.

3. Wallet lokal einrichten

Für den Kauf benötigen Sie eine eigene Käuferwallet mit USDC auf Base. Die x402-Abwicklung übernimmt die Gasgebühr dieses Kaufs. Tragen Sie den Schlüssel ausschließlich lokal in eine Datei .env.buyer ein. Datei und Schlüssel gehören weder in einen Chat noch in Git oder ein Webformular.

BUYER_PRIVATE_KEY=YOUR_DEDICATED_BUYER_KEY
MERCHANT_ADDRESS={{PAY_TO_ADDRESS}}

Der angegebene Empfänger ist die Betreiberwallet. Das Beispiel prüft diesen Wert zusätzlich gegen die tatsächliche Zahlungsanforderung. Eine andere oder höhere Zahlungsanforderung wird nicht freigegeben.

4. Genau einen Kauf freigeben

Wählen Sie REST oder MCP. Der folgende REST-Befehl erlaubt einen einzigen SERP-Kauf bis zum angezeigten Betrag. Er löst eine echte USDC-Zahlung aus.

chmod 600 .env.buyer
APPROVE_USDC={{SERP_PRICE}} node --env-file=.env.buyer buyer.mjs

Die Antwort wird in agent-api-purchase.json gespeichert (Dateirechte 600), einschließlich Anfragekennung und Ergebnis-Token. Der Schlüssel und die Zahlungsunterschrift werden nicht gespeichert. Bewahren Sie diese Datei privat auf und löschen Sie sie nicht, um einen unklaren Kauf erneut zu versuchen.

MCP verwenden

Endpoint: {{BASE_URL}}/mcp, Streamable HTTP. Die folgende Konfiguration verbindet einen passenden MCP-Client mit den vier kostenlosen Werkzeugen. Die genaue Konfigurationsform hängt vom Client ab.

{
  "mcpServers": {
    "agent-data-api": {
      "type": "http",
      "url": "{{BASE_URL}}/mcp"
    }
  }
}

list_services liest den Katalog; preflight prüft die Eingabe. get_result holt vorhandene Ergebnisse mit Token ab. retry_request ist eine ausdrückliche Wiederholung eines bezahlten, fehlgeschlagenen Abrufs und löst einen neuen Datenabruf aus. Das Verbinden allein zahlt nichts.

Für bezahlte Werkzeuge benötigt der Käuferclient x402-Unterstützung. Ein gewöhnlicher MCP-Client erhält nur die Zahlungsanforderung. Nutzen Sie alternativ im selben Beispiel einen einzelnen MCP-Kauf anstelle des REST-Kaufs:

APPROVE_USDC={{SERP_PRICE}} node --env-file=.env.buyer buyer.mjs --mcp

Das Beispiel verwendet @x402/mcp und prüft dieselben Grenzen wie bei REST. Es gibt keine pauschale Freigabe für andere Werkzeuge oder weitere Zahlungen.

Wenn eine Antwort fehlt

Bei Timeout, Verbindungsabbruch oder einer Fehlermeldung nach dem Senden der Zahlungsfreigabe ist eine fehlende Antwort kein Beweis für eine fehlende Zahlung. Nicht automatisch erneut kaufen oder eine neue Zahlungsfreigabe erzeugen.

  1. Vorhandene Kaufdatei und öffentliche Transaktionskennung aufbewahren.
  2. Mit vorhandener Anfragekennung und Ergebnis-Token den gespeicherten Vorgang abrufen:
curl {{BASE_URL}}/api/v1/results/REQUEST_ID \
  -H 'Authorization: Bearer RESULT_TOKEN'

Das Token gehört zur privaten Antwort. Bei einer ganz verlorenen Antwort kann derselbe ursprünglich signierte REST-Aufruf innerhalb von 15 Minuten das gespeicherte Ergebnis liefern, wenn Sie ihn noch sicher lokal vorliegen haben. Das Beispiel speichert keine Signatur; wenn Anfragekennung/Token fehlen, wenden Sie sich mit dem öffentlichen Zahlungsbeleg an {{CONTACT_EMAIL}}. Keine Schlüssel oder Signaturen senden.

Nach einem bestätigten Upstream-Fehler erlaubt der Dienst eine ausdrückliche kostenlose Wiederholung unter POST /api/v1/results/REQUEST_ID/retry mit demselben Bearer-Token. Die Entscheidung erfolgt erst nach Prüfung des Vorgangs; keine neue USDC-Zahlung. Eingaben und Ergebnisse werden nach 30 Tagen gelöscht.
